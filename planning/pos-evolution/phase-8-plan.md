## Goal

A Stock/Store Manager returns goods from a chosen PO receipt; stock leaves that receipt's batches; a numbered credit note lowers the source bill first and the rest becomes supplier credit a manager applies by hand. Supplier cheques start Issued and are Cleared or Bounced once; a bounce puts the amount back on the bill.

## Design (binding for builders)

- **Models (inventory app).** `SupplierReturn(number, receipt FK PROTECT, supplier, purchase_order, bill FK nullable, reason required, created_by, created_at)`; `SupplierReturnLine(return, receipt_line FK GoodsReceiptItem PROTECT, qty in the line's package unit, base_qty, credit_value)`; `SupplierReturnDeduction(line, batch FK PROTECT, qty, unit_cost_landed snapshot)` mirroring `SalesItemDeduction`; `SupplierCreditNote(number CN-YYYYMMDD-NNNN unique, return 1:1, supplier, source_bill nullable, value, vat_rate, vat_inclusive, vat_amount, total_amount, remaining_amount ≥0)`. All append-only like `SupplierBill` (immutable fields + refused delete); only `remaining_amount` moves, under lock.
- **Numbering:** add `CN` (and `SR` if returns get their own number; default: return shows its credit-note number only) to `COUNTER_SOURCES`, call `pos.services.next_number` via a function-local import inside the return transaction (inventory already lazy-imports pos models in `serializers.py:135`).
- **Stock-out:** quantity entered in the receipt line's unit (`po_item.variant_uom`), converted with `line_factor`, whole-unit rule and `refuse_unrepresentable_stock`. Cap per line = min(line base qty − base already returned on that line, Σ`current_qty` of batches with `receipt=<chosen>` and that variant). New `allocate_from_receipt(receipt, variant, base_qty)`: `select_for_update` batches filtered by **receipt + variant**, PK order, oldest first; writes one deduction row per batch touched; refusal `RETURN_EXCEEDS_RECEIPT` (400) writes nothing. Phase 9 compatibility: filter by `receipt`, never by location; Phase 9 transfers copy `receipt` onto destination batches, so returns keep working wherever the stock sits.
- **Credit value:** Σ(base qty × batch `unit_cost_landed`) over deductions, rounded once with `money`. VAT from the source bill snapshot (`vat_rate`, PO `vat_inclusive`) via `vat_split`: inclusive → total = value, VAT extracted; exclusive → total = value + VAT. No bill (pre-Phase-5 receipt or zero-value delivery): PO snapshot, whole total becomes supplier credit.
- **Apply rule (one transaction):** lock source bill → applied = min(total, bill.balance) → create `SupplierPayment(method=CREDIT, credit_note, amount=applied, status=CLEARED)` and lower `balance_amount` → `remaining_amount = total − applied`. Manual apply: `POST /supplier-payments/` `{bill, amount, method: CREDIT, credit_note}`; same supplier required, amount ≤ min(note remaining, bill balance) (`CREDIT_EXCEEDS_REMAINING`/`OVERPAYMENT`), lock order note → bill; Store Manager/Admin only. CREDIT is never chosen with cheque fields; the plain method list refuses CREDIT without `credit_note`.
- **Cheque status:** `SupplierPayment.status` ISSUED/CLEARED/BOUNCED + `decided_by`, `decided_at`, `decision_reason`, `credit_note` FK nullable, `Method.CREDIT`. Migration: AddField default CLEARED, so every existing row (cheques included) is CLEARED; new CHEQUE rows are created ISSUED, all others CLEARED. `save()` relaxes to allow exactly `update_fields ⊆ {status, decided_by, decided_at, decision_reason}` when the stored status is ISSUED; everything else still raises `ImmutablePayableRecord`.
- **Decide:** `payables.decide_supplier_cheque(payment_id, decision, user, reason)` copies `decide_cheque`: bounce reason required (`CHEQUE_REASON_REQUIRED`), lock payment then bill (no cycle: `record_supplier_payment` never locks payments), re-read, non-ISSUED → `CHEQUE_ALREADY_DECIDED` 409. CLEARED moves no money; BOUNCED adds `amount` back to `balance_amount` (assert ≤ total). Endpoints `POST /supplier-payments/{id}/clear|bounce/`, queryset filtered to CHEQUE (non-cheque → 404), `IsManagerRole`, `CHEQUE_DECISION` audit in the same atomic block.
- **Audit:** new `AuditLog.ActionType.SUPPLIER_RETURN` ('Supplier Return') via one users migration (next after the leaf at dispatch). Credit application (auto and manual) audits as `PAYMENT`; decisions as `CHEQUE_DECISION`.
- **Roles:** return create/read, credit notes read: `IsInventoryRole`. Apply credit, clear/bounce: `IsManagerRole`. Cashier/CPMS refused everywhere.
- **Low stock:** `check_low_stock_after_stock_out(variant_ids=…)` inside the return transaction.
- **Supplier balance math:** owed = Σ`balance_amount` (already bills − payments − applied credit, since CREDIT is a payment); `/suppliers/payables/` adds `credited` (Σ CREDIT payments), `paid` = original − balance − credited, `unapplied_credit` = Σ note `remaining_amount` — shown separately, never subtracted into a negative balance; `issued_cheques` = Σ ISSUED cheque amounts (informational).
- **RETURN adjustment retired:** `StockAdjustmentSerializer` (`serializers.py:999`) refuses new `adjustment_type=RETURN` (`USE_SUPPLIER_RETURN`, 400); historical rows keep their label. Flutter adjust dialog drops "Supplier Return".
