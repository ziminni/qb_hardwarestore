## Goal

Stock is counted per location. Every stock writer knows where stock sits; sales/releases take home first then elsewhere; one-step numbered transfers move stock with cost and age; low stock stays on the total and shows the split.

## Design (binding for builders)

1. **Batch location + migration.** `InventoryBatch.location` FK `StorageLocation` PROTECT. Migration (next free inventory number after Phase 8's): add nullable → `RunPython` sets `location = variant.product.stored_at_id` for every batch (decision 21 §1) → alter non-null; reverse is noop + drop. `StockAdjustment.location` same three steps (backfill from product). A batch's location is **immutable** after creation (transfers create new batches), so `SalesItemDeduction.batch.location` is a stable "where it was taken" — no new deduction column; pinned by a test.
2. **Transfer-born batches vs receipt sums.** `InventoryBatch.receipt` is non-null; a transfer batch **copies** the source receipt, landed cost, selling price, markup, expiry. Add `InventoryBatch.source_batch` FK self, null (set on transfer/adjust-born batches). Every "what this receipt brought in" sum filters `source_batch__isnull=True`: legacy delta `services.py:176-178`, movements report `reports/views.py:150`, and any later `initial_qty`-by-receipt sum (Phase 8's `allocate_from_receipt` caps by receipt-line qty and filters by `receipt`, so it already works across locations — re-check at dispatch). FIFO order stays `receipt__receive_date`, then `id` (age survives the move).
3. **Location-aware allocate.** `allocate_fifo(variant_id, qty_needed)` keeps its signature; one locked query orders batches: home (`variant.product.stored_at`) first, then other locations by location pk, FIFO within (`receipt__receive_date`, `id`). Optional `location_id=` restricts to one location (adjust removal, transfer). Inactive non-home stock: see Q1. Returned `(batch, take)` list unchanged, so `process_sale` (and Phase 7 fulfilment through it) needs no change beyond captions. `release_materials` starts writing `SalesItemDeduction` rows like `process_sale` `:896-904`. `_on_hand_base`/`_release_plan` count the same set the allocator takes.
4. **Pick-up captions.** Sale line + release + delivery-slip item gain `pick_up: [{location, location_name, qty, unit}]` grouped from deductions in allocation order. `qty` is in the line's selling unit when every part divides exactly, else in base units with the base code (e.g. 1 BOX of 12 split 7/5 → "7 PC at Store, 5 PC at Bodega"). No deductions (pre-Phase-9 or order not yet fulfilled) → single entry from `stored_at` (today's caption). `stored_at`/`stored_at_name` stay for old clients.
5. **Per-location on-hand API.** `GET /api/v1/stock-on-hand/` (any authenticated, like `/batches/`): one `values(variant, location).annotate(Sum)` query → rows `{variant, location, location_name, location_active, is_home, qty}`, filter `?variant=`. Clients stop summing `/batches/` for quantity (cost/valuation dashboards may keep `/batches/`, which gains `location`, `location_name`, `source_batch`).
6. **StockTransfer.** Header `StockTransfer(number "TR-YYYYMMDD-NNNN" via `next_number`, from_location, to_location, user, remarks, created_at)`; lines `StockTransferLine(transfer, variant_uom, qty in selling unit, base_qty)` + `StockTransferMove(line, source_batch, dest_batch, qty)`. Append-only (no PUT/PATCH/DELETE → 405). Roles `IsInventoryRole`. Qty converted to base with the whole-unit and two-decimal rules (`refuse_unrepresentable_stock`-style refusal, no writes). Refusals: same location, inactive destination, archived variant, short stock at source (`InsufficientStock` with location in message), empty lines. New audit action `STOCK_TRANSFER` (users AuditLog choice + migration). Low-stock re-check not needed (total unchanged).
7. **Receiving destination.** `GoodsReceiptLine.location` FK null; receipt POST accepts optional per-line `location` (default home, must be active → `INVALID_STORAGE_LOCATION`); `_create_batch` stamps it; legacy no-lines path uses home.
8. **Adjustments.** Payload `location` optional (default home). Removal = `allocate_fifo(location_id=…)`. Addition reopens newest batch **at that location**; none there → new batch copying the variant's newest batch (receipt/cost/expiry, `source_batch` set); no batch anywhere → `NoBatchHistory` (unchanged). Inactive location refuses additions; removals allowed (stock stays manageable).
9. **Returns.** Linked: unchanged (deduction batches ⇒ location left). Unlinked fallback: newest batch at **home** first, then newest elsewhere, then newest overall. Phase 8 supplier returns: receipt's batches incl. transfer-born ones, any location.
10. **Low stock.** `_check_low_stock` keeps the total; alerts unchanged. Low-stock list/table shows split from the on-hand API.
11. **Inactive location.** Cannot receive, be adjusted into, or be a transfer destination; stock there stays visible, transferable out, and (pending Q1) sellable. Deactivation does not move stock.
12. **Lock order** (all writers, inside one atomic): (a) target/destination `StorageLocation` row `select_for_update` (fences deactivation race), (b) batches per variant, variants in PK order, each variant's batches in one ordered query, (c) `ProductVariant` row via `_check_low_stock` (already after batches), (d) `DocumentCounter` via `next_number` last. Multi-line transfers process lines in variant-PK order.

## Owner questions (defaults used unless overridden)

- **Q1 inactive stock sellable?** Decision §2 says "home, then any other **active** location"; delegated default says inactive stock "stays sellable"; Consequences say availability = "total across active locations". **Default: home first, then active others, then inactive others** — allocator and availability agree, no stranded stock.
- **Q2 split caption unit:** base units when a selling unit splits across locations (Design 4). Alternative: allocator avoids splitting one selling unit.
